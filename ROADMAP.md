- «3 качества, без которых не вижу семью», «3 ред-флага», «главные страхи о браке» — отличные диалоговые вопросы, ложатся в предпочтения/профиль.

Психологический разбор (→ Э2, профиль):
- интроверт/экстраверт — измеримо, ок; психотипы Нэнси Маквильямс (тест) ⚠️ *валидность самотеста под вопросом*.
- ⚠️ **«улавливать адекватность / маниакальные наклонности из переписки»** — псевдо-психиатрия, спецкатегория данных, юридический и этический риск; допустимо только как мягкий сигнал модерации шадхану-человеку, не как диагноз.
- ⚠️ **заболевания / депрессия / антидепрессанты** — данные о здоровье (спецкатегория ПДн, 152-ФЗ); нельзя слать во внешний LLM без обезличивания.

Аналитика (ответ на вопрос с первого созвона): 684 анкеты (57%) — самостоятельные регистрации (418 с подтверждённой почтой), 504 (42%) завели 11 шадханов вручную, 1 сирота.

### Идея: приглашение по ссылке от шадхана

Шадхан заводит анкету-заготовку → генерит персональную ссылку → кандидат по ней заходит без полной регистрации и дозаполняет через ИИ-консультанта. Решает «человек не хочет регистрироваться сам». Новая фича — раздел XI (ниже).

## Раздел X. Обработка чувствительных данных (сквозное, решения встречи 2026-08-18)

*Правило действует во всех фазах, где данные уходят в LLM (Э1, Э2, Э3).*

- ⬜ **X-4.** Психотипы Маквильямс — мягкая адаптация «ориентир для шадхана», с оговоркой о невалидности самотеста; не выдавать за диагноз

## Раздел XI. Приглашение по ссылке от шадхана (приоритет заказчика)

*Разблокировано. Делать после Э0.3. Решает боль: 42% базы — ручной ввод 11 шадханами; многие кандидаты не хотят регистрироваться сами.*

**Решения (подтверждены заказчиком 2026-08-19):** (1) **аккаунт-заготовка** — «Пригласить» создаёт кандидату отдельный аккаунт (`Checked=1`, группа кандидата, синтетический email `invite-<токен>@invite.shiduh.org`, случайный пароль) поверх уже заведённой шадханом анкеты, `Shadhan_1`=шадхан; (2) ссылка **многоразовая до присвоения + срок 30 дней**; (3) отправка — **копировать ссылку + опционально email** через `nc_mail2queue`.

**Архитектура (проверено по коду):** переиспользуем авторизацию NetCat — `nc_user::authorize_by_id($candidate_user_id)` создаёт сессию по ID (требует `Checked=1` + запись в `User_Group`). Криптографический `authorize_by_token` (ECDSA/Auth_Token) НЕ берём — избыточен. Кандидат по токену логинится в свой аккаунт-заготовку и дозаполняет анкету через уже готовый `/my/ai-consultant/` (чат и проверки владения завязаны на `User_ID` — всё работает без изменений).

- ✅ **XI-1.** Миграция 007: таблица `invite_tokens` (`token` CHAR(64) UNIQUE, `candidate_user_id`, `created_by` [шадхан], `created_at`, `expires_at`, `used_at`, `claimed_at`), индексы по `token`/`candidate`/`created_by`. Обратима. Тесты `migrations_test.py` 24/24
- ✅ **XI-2.** `api/invite_create.php` (POST, только шадхан). Работает **поверх уже заведённой анкеты** (у `Message204` много NOT NULL-полей без дефолта под strict-mode). Проверяет, что шадхан ведёт анкету (владелец или `Shadhan_N`) **и** что передавать владение безопасно — анкетой владеет сам шадхан или заготовка, а не реальный кандидат (иначе 409, чтобы не отобрать анкету у зарегистрированного). Создаёт кандидату аккаунт-заготовку (`user->add`, группа 2, `Type=1`, `Checked=1`, синтетический email, случайный hex-пароль, обязательные поля User из анкеты); пишет `invite_tokens` (токен `bin2hex(random_bytes(32))`, 30 дней) **до** передачи владения (проверка `is_error` — не оставить мёртвую ссылку); затем `Message204.User_ID`→заготовка, `Shadhan_1`=шадхан. - ✅ **XI-3.** `api/invite.php` (GET `?t=`). Валидирует формат `^[0-9a-f]{64}$`, существование, `expires_at`, `claimed_at`; помечает `used_at`; `authorize_by_id($candidate_user_id)` (ставит cookie сессии) → 302 на `/my/ai-consultant/`. Битый/истёкший — нейтральный 404, присвоенный — 410 (не раскрываем причину). Тесты входа: редирект+cookie, сессия авторизована как кандидат, негативы

Кандидат задаёт свой email+пароль: формат email — явный `nc_check_email` (штатный `check_login` не проверяет: Format поля = `email:`, а не `email`), уникальность — `check_login`, пароль ≥6. Меняет ТОЛЬКО свой аккаунт (по сессии), гасит токен(ы) (`claimed_at`). Форма в консультанте (`class/323/FormPrefix.html`) — только для заготовок (детект по email).
