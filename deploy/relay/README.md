# Пересылка запросов к модели

Зачем это нужно и что тут лежит.

## Задача

С российского адреса `openrouter.ai` отвечает **403 «Access denied by security
policy»** на любой запрос, включая публичный список моделей. Проверено
2026-09-10 с VPS Beget в Санкт-Петербурге. Это отбой по стране на стороне
Cloudflare, ключ и настройки ни при чём.

Перенести сайт за границу нельзя: база с реальными анкетами по закону должна
оставаться в России, а в анкетах не только имена и телефоны, но и сведения о
здоровье и документы. Поэтому за границу выносится **только пересылка
запросов к API**. Сайт, база и файлы остаются на месте.

Адрес провайдера — настройка `base_url` на `/admin-ai.php`, поэтому
переключение не требует правок кода.

## Что делает

`Caddyfile` поднимает Caddy, который принимает запросы **только с адреса
нашего сервера приложения** и передаёт их на `openrouter.ai`. Сертификат
выпускается автоматически.

Ограничение по адресу — не перестраховка. Без него получается открытый прокси
к платному API: адрес найдут сканеры за считаные часы, и счёт оплатит
владелец ключа.

## Как поднять

На зарубежном сервере с Docker:

```bash
mkdir -p /opt/shiduh-relay
# положить сюда deploy/relay/Caddyfile, заменив в нём:
#   - имя сайта на своё (или <ip-через-дефис>.sslip.io для временного);
#   - remote_ip на адрес своего сервера приложения.

docker run -d --name shiduh-llm-relay --restart unless-stopped \
  -p 80:80 -p 9443:9443 \
  -v /opt/shiduh-relay/Caddyfile:/etc/caddy/Caddyfile:ro \
  -v shiduh-relay-data:/data \
  caddy:2-alpine

docker logs shiduh-llm-relay | grep "certificate obtained"
```

Порт 9443, а не 443, потому что на машине, где это поднималось впервые, 443
был занят. Если 443 свободен, проще взять его и убрать из настройки блоки
`https_port` и `disable_tlsalpn_challenge`: тогда порт 80 не понадобится.

Проверка — **с сервера приложения**, не откуда попало:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://<адрес-пересылки>:9443/api/v1/models
# 200 — работает. С любой другой машины должно быть 403.
```

Дальше на `/admin-ai.php`: `base_url` = `https://<адрес-пересылки>:9443/api/v1`,
провайдер `openrouter`, ключ, модель. Затем «Проверить подключение».

## Чего здесь нет и почему

Ключ провайдера в этих файлах не хранится и через них не проходит в открытом
виде: он лежит в настройках сайта и уходит в заголовке по TLS до пересылки и
от неё до OpenRouter.

## Что учесть

- Пересылка становится точкой отказа: упала она — у сайта молча отвалился
  консультант. Её стоит держать на отдельной машине, а не на сервере,
  который переустанавливают ради другой задачи.
- Отправка кусочков анкет в зарубежную модель — трансграничная передача
  данных. Здоровье, доходы и медикаменты в модель не уходят вообще
  (`api/ai_sensitive_fields.php`), но текст согласия должен это покрывать.
- Альтернатива без второй машины — российский посредник с
  OpenAI-совместимым API: меняется тот же `base_url` и ключ. Сравнение
  вариантов — в `docs/REPORT.md` §5.
