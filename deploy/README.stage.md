# Тестовый стенд — ранбук

Как поднять копию shiduh.org на отдельном VPS. Рассчитано на то, что выполнять будет человек с доступом к серверу — знание проекта не требуется.

> **Стенд работает только на обезличенных данных.** Боевую базу на него не заливать: п.1 запретов ТЗ. Почта на стенде перехватывается и наружу не уходит.

---

## Что понадобится

| Что | Требование |
|---|---|
| VPS | Ubuntu 22.04 или 24.04, **2 ГБ RAM**, 40 ГБ диска |
| Домен | Поддомен вида `stage.shiduh.org`, A-запись на IP сервера. Пока его нет — годится `<ip-через-дефис>.sslip.io`, он резолвится в этот IP сам и сертификат на него выпускается |
| Доступ | SSH-ключ, root на первый запуск |
| Файлы | Обезличенный дамп (~30 МБ) и папка `netcat_files` (~2,7 ГБ) |

**Почему 2 ГБ.** MySQL 5.7 с настройками проекта берёт около 400 МБ, PHP-контейнер около 200 МБ, сборка образа — ещё столько же. На 1 ГБ сборка падает по нехватке памяти.

**Почему нужен домен, а не голый IP.** Guard'ы в шаблонах делают `header('Location: https://'.$_SERVER['HTTP_HOST'])` с захардкоженной схемой (находка №16а в `AUDIT.md`). Без TLS неавторизованный пользователь получит не редирект на главную, а обрыв соединения. Сертификат Caddy выпускает сам, но для этого нужен домен.

---

## Первый запуск

### 1. Подготовить машину

```bash
ssh root@<ip>
curl -fsSL https://raw.githubusercontent.com/<репозиторий>/main/deploy/bootstrap-vps.sh -o bootstrap.sh
# или просто скопируйте файл deploy/bootstrap-vps.sh на сервер
bash bootstrap-vps.sh
```

Скрипт ставит Docker, заводит пользователя `shiduh`, закрывает файрвол (наружу — только SSH, 80 и 443) и выключает вход по паролю.

### 2. Забрать код

```bash
ssh shiduh@<ip>
git clone <репозиторий> shiduh && cd shiduh
```

### 3. Настроить окружение

```bash
cp .env.example .env
nano .env
```

Заполнить:

```ini
STAGE_DOMAIN=stage.shiduh.org
STAGE_USER=team
STAGE_PASS_HASH=<хеш, см. ниже>

NC_MYSQL_PASSWORD=<длинный случайный>
MYSQL_ROOT_PASSWORD=<другой длинный случайный>
```

Пароли сгенерировать на сервере, не придумывать руками:

```bash
openssl rand -base64 24
```

Хеш для входа на стенд:

```bash
docker run --rm caddy:2-alpine caddy hash-password --plaintext 'ваш-пароль'
```

Полученную строку (начинается с `$2a$`) вписать в `STAGE_PASS_HASH`. Если правите `.env` вручную — экранируйте `$` как `$$`, иначе Compose съест их как подстановку переменных.

### 4. Залить данные

С рабочей машины:

```bash
# обезличенный дамп
scp dump-out/dump.anonymized.sql shiduh@<ip>:~/shiduh/dump-out/

# загрузки пользователей (2,7 ГБ, идёт долго; rsync можно возобновить)
rsync -avz --progress shiduh.org/netcat_files/ shiduh@<ip>:~/shiduh/shiduh.org/netcat_files/
```

Без `netcat_files` стенд поднимется, но анкеты будут с битыми фотографиями.

### 5. Поднять

```bash
cd ~/shiduh
docker compose -f docker-compose.stage.yml up -d --build
docker compose -f docker-compose.stage.yml ps
```

### 6. Залить базу и настроить домен

```bash
C="docker compose -f docker-compose.stage.yml"

# импорт обезличенного дампа
$C exec -T db sh -c 'mysql -uroot -p$MYSQL_ROOT_PASSWORD -e "
  DROP DATABASE IF EXISTS shiduh_org;
  CREATE DATABASE shiduh_org DEFAULT CHARACTER SET utf8 COLLATE utf8_general_ci;
  GRANT ALL ON shiduh_org.* TO shiduh_org@\"%\"; FLUSH PRIVILEGES;"'
$C exec -T db sh -c 'mysql -uroot -p$MYSQL_ROOT_PASSWORD \
  --init-command="SET SESSION sql_mode=\"NO_AUTO_VALUE_ON_ZERO\"" shiduh_org < /out/dump.anonymized.sql'

# проверить, что данные действительно обезличены
$C exec -T db sh -c 'mysql -uroot -p$MYSQL_ROOT_PASSWORD -t shiduh_org < /tools/03_verify.sql'

# привязать к домену стенда и продлить демо-лицензию
$C exec -T db sh /tools/05_set_domain.sh stage.shiduh.org
```

Шаг с `03_verify.sql` — не формальность. Если хоть одна проверка не пройдёт, значит на стенд приехали неотмытые данные, и дальше идти нельзя.

### 6.5. Миграции и настройки

Дамп — снимок боевой схемы. Всё, что сделано после него, накатывается
миграциями; без них не будет ни чата, ни согласий, ни админ-консоли.

```bash
C="docker compose -f docker-compose.stage.yml"

$C exec -T web php /var/www/html/migrations/migrate.php up
$C exec -T web php /var/www/html/migrations/migrate.php status   # 001–013, 015–027
```

Дальше — на самом стенде, под администратором:

- `/admin-ai.php` — провайдер, ключ, модель (`mistralai/mistral-small-2603`,
  обоснование в `docs/REPORT.md` §4), затем «Проверить подключение».
  **С российского адреса OpenRouter отвечает 403** — см. «Доступ к модели».
- `/admin-ai.php`, блок капчи — серверный секрет SmartCaptcha, если он уже
  получен; без него капча проверяется только в браузере.

Убрать статическую заглушку, если она приехала с дампом файлов:

```bash
$C exec -T web rm -f /var/www/html/index.html
```

Cron поздравлений (по желанию, стенд без него работает):

```bash
$C exec -T web sh -c 'echo "0 9 * * * www-data php /var/www/html/check_birthday_candidates/index.php" > /etc/cron.d/shiduh-birthday'
```

## Доступ к модели с российского сервера

Проверено 2026-09-10 с VPS Beget (Санкт-Петербург): `https://openrouter.ai`
отвечает **403 «Access denied by security policy»** на любой запрос, включая
публичный список моделей. Это отбой по стране на стороне Cloudflare, ключ и
настройки ни при чём.

Проверить на своём сервере:

```bash
curl -s -o /dev/null -w "%{http_code}
" https://openrouter.ai/api/v1/models
# 200 — доступ есть; 403 — закрыт по стране
```

Адрес провайдера вынесен в настройку `base_url` на `/admin-ai.php`, поэтому
сам сайт переносить не нужно — достаточно направить его на посредника.
Варианты решения — в `docs/REPORT.md` §5.

### 7. Проверить

Открыть `https://stage.shiduh.org` — браузер спросит логин и пароль из `.env`, дальше должен отдаться сайт.

Пароль всех учётных записей после обезличивания: `shiduh`.

## Приёмочный чек-лист

Пройти целиком после первого запуска и после каждой выкатки.

- [ ] Главная отдаёт 200, демо-модалки NetCat нет
- [ ] Вход под кандидатом работает
- [ ] Вход под шадханом работает, в меню видны «Поиск шидуха», «Создание шидуха», «Мои кандидаты»
- [ ] `/my/candidate/` — поиск возвращает результаты
- [ ] Карточка кандидата открывается, фотографии грузятся
- [ ] Регистрация нового пользователя проходит
- [ ] **Письмо пришло в mailpit, наружу не ушло** (см. туннель ниже)
- [ ] Английская версия `/en/` открывается
- [ ] Админка `/netcat/admin/` открывается
- [ ] `03_verify.sql` — все проверки зелёные
- [ ] В логах Caddy нет обращений от поисковых роботов (заголовок `X-Robots-Tag` на месте)
- [ ] `migrate.php status` — применены 001–013 и 015–027
- [ ] `/admin-ai.php` открывается администратору, «Проверить подключение» — ok
- [ ] Консультант отвечает, **текст печатается по мере ответа**, а не появляется
      целиком в конце (если появляется целиком — сжатие Caddy задело SSE)
- [ ] Кнопка «Остановить» обрывает ответ, начатый текст сохраняется в истории
- [ ] Консультант записывает факт в анкету; заполненное поле меняет только
      после «да» (в ответе видна пометка «пока не изменено»)
- [ ] Мастер анкеты: семь шагов, возраст меньше 18 не проходит, черновик
      переживает перезагрузку страницы
- [ ] `/admin-moderation.php`, `/admin-consent.php`, `/admin-matches.php`
      открываются администратору и отдают 403 кандидату
- [ ] Часы: `SELECT NOW()` в базе совпадает с московским временем

## Доступ к почте и базе

Наружу они не открыты намеренно. Подключение — через SSH-туннель:

```bash
ssh -L 8025:127.0.0.1:8025 -L 13306:127.0.0.1:13306 shiduh@<ip>
```

Дальше на своей машине:
- почта стенда — `http://localhost:8025`
- база — `localhost:13306`, пользователь `shiduh_org`

## Повседневное

```bash
C="docker compose -f docker-compose.stage.yml"

$C logs -f web          # логи приложения
$C logs -f proxy        # логи TLS и входа
$C restart web          # перезапуск после правки php.ini
$C pull && $C up -d     # обновить образы

# выкатить новую версию кода
git pull && $C up -d --build

# полный сброс данных стенда
$C down -v && $C up -d --build   # затем повторить шаг 6
```

## Чего на стенде быть не должно

| Нельзя | Почему |
|---|---|
| Боевая база | п.1 запретов ТЗ; на стенде только обезличенные данные |
| Настоящий SMTP | стенд разошлёт письма живым пользователям — уже почти случилось на проде из-за захардкоженного домена в cron |
| Открытые наружу 8025 и 13306 | почта и база без авторизации |
| Индексация поисковиками | закрыто базовой авторизацией и `X-Robots-Tag` |
| Ключи боевых сервисов | платёжные шлюзы — только тестовые. Ключ LLM на стенде живой, но с лимитами: на `/admin-ai.php` держите `rate_limit_per_hour` 30 и `burst_per_minute` 6, иначе один зациклившийся диалог съест баланс |

---

## Если что-то не работает

| Симптом | Причина |
|---|---|
| Caddy не выпустил сертификат | A-запись домена ещё не разошлась, либо 80-й порт закрыт файрволом |
| Сайт отдаёт 502 | контейнер `web` не поднялся, смотреть `$C logs web` |
| Открывается, но вместо страниц редирект в никуда | `Catalogue.Domain` в базе не совпадает с доменом — перезапустить шаг 6 |
| Модалка «пробный период закончился» | демо-лицензия протухла, перезапустить `05_set_domain.sh` |
| `short_open_tag value must be on!` | не подключился `docker/php/php.ini` |
| Битые фотографии в анкетах | не залит `netcat_files` |
| Сборка падает по памяти | на VPS меньше 2 ГБ RAM |
