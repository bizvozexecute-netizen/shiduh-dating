## 2. Что сделано по разделам

### Безопасность
- Закрыта живая регрессия: после ротации `SecretKey` любое сообщение с фото
  падало на проверке хэша виджета — хэш теперь печатается ядром.
- SQL-инъекции и XSS закрыты во всех копиях шаблонов, включая публичные
  разделы `/news/`, `/events/`; open redirect через `Referer` убран.
- CSRF-заслон на всех изменяющих эндпоинтах (источник запроса + токен), единые
  проверки прав (кандидат / шадхан / администратор / суперадмин).
- Вход по приглашению — через межстраницу, а не логин по GET-ссылке.
- Загрузки анкеты: лимит размера, тип по реальным байтам, запрет исполнения
  в `netcat_files/`.
- Пароли: MD5 → bcrypt с прозрачным переходом при входе.
- SmartCaptcha проверяется на сервере (включается секретом в настройках).
- Регистрация: порог 18 лет, правила пароля и согласие проверяются на сервере.
- Наблюдаемость: ошибки пишутся в лог, фаталы в `api/` отвечают JSON 500 без
  подробностей.

### ИИ-консультант (чат)
- Потоковый ответ (SSE) с автоматическим откатом на обычный JSON, честный
  индикатор ожидания, кнопка «Остановить».
- Markdown-lite без выполнения HTML; история постранично; треды; оценки ответов.
- Приветствие консультанта и подсказки-чипсы по незаполненным полям.
- Автозаполнение анкеты из диалога через инструменты; заполненное поле меняется
  **только после подтверждения** человека; сервер дописывает к ответу модели,
  что именно ещё не записано (модели склонны говорить «записал» раньше времени).
- Учёт расхода токенов и потолок ответа; ценностный опрос синхронизирован с
  чатом; «Мои пары» грузятся лениво.
- Деликатные данные (здоровье, доход, медикаменты) во внешнюю модель не уходят
  — реестр `api/ai_sensitive_fields.php`, закреплено тестами.

### Интерфейс
- Дизайн-слой на токенах поверх бандла без сборки: `css/one.css` (84 КБ),
  `js/one.js` (15 КБ), каталог компонентов, motion с уважением к
  `prefers-reduced-motion`.
- Лендинг с числами из базы, липкая шапка, модальные окна входа; кабинет и
  сообщения; витрина с постраничностью в SQL (24 на страницу) и миниатюрами.
- Карточки кандидата: шапка-герой, подменю разделов, скрипты и стили вынесены
  из шаблонов.
- Мастер анкеты из семи шагов с серверной проверкой (возраст, рост, телефон,
  почта), общая разметка для добавления и правки, черновик в браузере без
  деликатных полей.
- Доступность: имена у элементов-иконок, подписи полей, заголовки, ориентиры;
  чеклист — `docs/A8-checklist.md`, скриншоты — `docs/screens/`.

### Админ-консоль (`/admin-*.php`)
- Каркас с CSP и nonce; «ИИ и подключение» (ключ, модель, лимиты, проверка
  подключения, расход); промпт консультанта; кейсы опроса; рассылка.
- Очередь «сигналов внимания» (закрывает администратор или ведущий шадхан).
- Согласия на сведения о здоровье: счётчики, список без самого поля, CSV,
  запрос повторного согласия письмом.
- Статистика подбора пар.

### Эксплуатация
- Cron поздравлений переписан (только CLI, без дублей), сломанная задача
  планировщика убрана миграцией.
- Единый часовой пояс MySQL и PHP.
- Ранбук выкатки `deploy/DEPLOY.prod.md`: порядок файлов, патчи ядра в «окно»,
  миграции 001–027, настройки, cron, логи, откат.

## 4. Живой провайдер и выбор модели

Живой ключ OpenRouter введён на стенде через `/admin-ai.php` (в git не хранится), и шесть моделей прогнаны инструментом `tools/live_bench.py` по одному сценарию: проверка подключения → новый диалог кандидата → факты для автозаполнения (город, рост, работа, увлечение) → «я переехал» → «да, поменяйте» → повторное «да» → вопрос из ценностного опроса → ответ → резюме кандидата и обоснование пары от шадхана. Замерялись обращения к модели, токены, задержки и стоимость по прайсу OpenRouter; протокол ответов читался целиком.

| Модель | Цена, $/1M вх/вых | Сценарий, $ | Обращений | Задержка ср./макс | Инструменты | Замечания |
|---|---|---|---|---|---|---|
| **mistralai/mistral-small-2603** — выбрана | 0.15 / 0.60 | 0.0042 | 13 | 1,7 с / 4,9 с | все шаги верно, предлагает и город, и «о себе» | короткие ответы по промпту (2–5 предложений), ни разу не сказала «записал» без записи |
| deepseek/deepseek-v4-flash | 0.07 / 0.14 | 0.0019 | 12 | 7,8 с / 34 с (в другом прогоне 3,8 / 7,9) | все шаги верно | самая дешёвая; всплески задержки, один раз «записал» без вызова инструмента |
| qwen/qwen3.8-flash | 0.15 / 0.47 | 0.0053 | 13 | 3,1 с / 8 с (до 16 с) | верно, две замены сразу | самые живые ответы, заметила, что ответ не на тот вопрос; многословна |
| google/gemini-3.1-flash-lite | 0.25 / 1.50 | 0.0050 | 11 | 1,6 с / 2,3 с | замена верно; факты не записала | самая быстрая; переспрашивает одно и то же |
| openai/gpt-4.1-nano | 0.10 / 0.40 | 0.0018 | 11 | 1,9 с / 2,8 с | факты не записала, «обновлю» без вызова | искажение в резюме («основную профессию — водителя») |
| openai/gpt-5-mini | 0.25 / 2.00 | 0.0117 | 9 | 8,2 с / 12 с | ни одного вызова | модель-«рассуждатель»: 4,6 тыс. токенов ушли в размышления, ответы и резюме пустые |

Выбор: **mistralai/mistral-small-2603**. Цена сценария из десяти реплик и двух генераций — меньше половины цента; при сотнях диалогов в месяц счёт — единицы долларов у любой из первых трёх, поэтому решали качество и стабильность: у mistral-small все инструментальные шаги прошли правильно с первого раза, задержка ровная, ответы короткие, как требует промпт. deepseek-v4-flash — запасной вариант, когда важна цена; qwen3.8-flash — когда важнее «живость» диалога. Переключение — на `/admin-ai.php`, код менять не нужно.

Что показал прогон и что исправлено: на ответ инструмента «поле уже заполнено — спросите» четыре модели из пяти отвечали «записал», хотя сервер ничего не менял. Теперь сервер сам дописывает к ответу, какое поле ещё не изменено и что предложено (`chat_append_pending_note` в `api/chat_lib.php`, тест `chat_overwrite_test.py`); замена применяется на следующем «да» через `confirm_profile_update` — этот двухшаговый порядок отработал у всех моделей. Заодно закрыт пробел: если модель повторяла вопрос в следующем ходу, сервер снимал его как «отвеченный», и «да» уже не срабатывало; теперь повторённый вопрос остаётся открытым. Ответ на кейс опроса, не отвечающий сценарию, модели корректно не записывали (qwen и mistral переспрашивали).

## 5. Что нужно для выкатки

1. Пройти `deploy/DEPLOY.prod.md` по порядку: бэкап, файлы (парами
   близнецов), патчи ядра в «окно», миграции `php migrations/migrate.php up`,
   сброс кэшей, smoke-проверка.
2. В `vars.inc.php` прода: `$MYSQL_TIMEZONE = "+03:00"`, секреты через
   переменные окружения (файл в git не хранится).
3. На `/admin-ai.php`: провайдер `openrouter`, ключ, модель из §4, лимиты по
   умолчанию; «Проверить подключение».
4. `Module='captcha'`: серверный секрет SmartCaptcha (сначала `fail_open=1`).
5. Системный cron поздравлений (DEPLOY §13); крон рассылок ядра — как раньше.
6. Удалить статический `index.html` из корня прода.

## 6. Что сознательно не делалось

- Монетизация (решение заказчика: всё бесплатно); тёмная тема; EN-версия
  (правилась только там, где инъекция достижима по URL).
- Апгрейды MySQL 8 и PHP 8 — отдельные проекты (см. ROADMAP B-6, B-7).
- Стирание данных о здоровье без указания заказчика — только инструменты
  (экран согласий, запрос повторного согласия).
- Ярлыки психотипов и хранение цитат переписки в сигналах внимания — по
  этическим и юридическим причинам (ROADMAP X-3/X-5).
